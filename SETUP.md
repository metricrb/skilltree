## Installation & Sync

**Wally vs this repo:** If you use SkillTree only as a Wally dependency, you get **`src/`** (see `exclude` in `wally.toml`: **`example`** and **`tests`** are omitted). Full-tree Rojo syncing and the Fusion **`example/`** playtest exist **only here** after `git clone`.

1. **Initialize Wally** (installs **ProfileStore** → `ServerPackages/` and **Fusion** → `DevPackages/` for the demo):
   ```bash
   wally install
   ```

2. **Install toolchain (recommended)** — [Aftman](https://github.com/LPGhatguy/aftman) installs a Rojo version **compatible with this repo**:

   ```bash
   aftman install
   ```

   `aftman.toml` pins Rojo to match the widely used Studio plugin (**7.2.x**, protocol **4**). Your **CLI and the [Rojo plugin](https://github.com/rojo-rbx/rojo/releases) must agree** — if Studio says protocol 5 and your CLI expects 4 (or the reverse), reinstall the plugin or change the pin in `aftman.toml`.

3. **Start Rojo**:
   ```bash
   rojo serve
   ```

4. **In Roblox Studio**:
   - Open the Roblox Studio Plugin menu → Rojo
   - Click "Connect" to sync the project

5. **Verify Sync**:
   - **`ReplicatedStorage.SkillTree`**: Full `src/` package (server + client requires).
   - **`ReplicatedStorage.SkillTreeDemo.ExampleConfig`**: Shared Fusion demo skill tree definition.
   - **`ReplicatedStorage.DevPackages`**: Wally **`[dev-dependencies]`** (Fusion 0.3 for the Fusion example)
   - **`ServerScriptService.ServerPackages`**: Wally **`[server-dependencies]`** (ProfileStore)
   - **`ServerScriptService.SkillTreeDemoServer`**: Runs `Example` server script (`SkillTree.new`, `PlayerAdded` / load + points).
   - **`StarterPlayer.StarterPlayerScripts.SkillTreeDemoClient`**: Runs `ClientDemo` LocalScript and `Components/` (requires **`ReplicatedStorage.DevPackages.Fusion`** from `wally install`).

## Module Hierarchy

All modules require `--!strict` and are fully typed via the `Types` module:

- **Types.luau** — Exported interfaces:
  - `NodeConfig`, `CategoryConfig`, `SkillTreeConfig`
  - `PlayerSkillState`, `Prerequisites`
  - `UnlockResult`, `RemoteConfig`

- **Signal.luau** — Lightweight event system (no external deps)

- **Validator.luau** — Pure prerequisite evaluation logic
  - `canUnlock(playerId, node, state, allNodes) -> UnlockResult`
  - `checkExclusivity(node, state, allNodes) -> UnlockResult`
  - `checkCapstone(node, state, allNodes) -> UnlockResult`

- **Store.luau** — [ProfileStore](https://github.com/MadStudioRoblox/ProfileStore) wrapper (`StartSessionAsync` / `EndSession`) for player persistence
  - `load(playerId) -> PlayerSkillState?`
  - `save(playerId, state) -> boolean`
  - `clear(playerId) -> boolean`

- **EffectHandler.luau** — Manages node unlock effects
  - `register(nodeId, callback)`
  - `apply(playerId, nodeId, rank, effectData)`

- **Network.luau** — RemoteEvent communication setup
  - `create() -> RemoteConfig`
  - `sendStateUpdate(playerId, state)`
  - `connectUnlockRequest(callback)`
  - `connectUpgradeRequest(callback)`

- **SkillTree.luau** — Server-side main class
  - `new(config) -> SkillTree`
  - `unlock(playerId, nodeId) -> UnlockResult`
  - `upgrade(playerId, nodeId) -> UnlockResult`
  - `respec(playerId) -> boolean`
  - Signal: `NodeUnlocked(playerId, nodeId, rank)`

- **SkillTreeClient.luau** — Client-side main class
  - `new(remoteConfig) -> SkillTreeClient`
  - `requestUnlock(nodeId)`
  - `requestUpgrade(nodeId)`
  - Signal: `StateUpdated(state)`

## API Patterns

### Server Initialization

```luau
local SkillTree = require(game:GetService("ReplicatedStorage"):WaitForChild("SkillTree"):WaitForChild("SkillTree"))

local config = {
  currencies = { "points" },
  layout = "branching",
  nodes = { /* ... */ },
}

local tree = SkillTree.new(config)

-- Optional: register custom effect handlers
tree._effectHandler:register("skill_id", function(playerId, nodeId, rank, effectData)
  -- Apply game-specific effect
end)

-- Player joins
Players.PlayerAdded:Connect(function(player)
  tree:loadPlayer(tostring(player.UserId))
end)

-- Player leaves
Players.PlayerRemoving:Connect(function(player)
  tree:unloadPlayer(tostring(player.UserId))
end)
```

### Client Integration

```luau
local SkillTreeClient = require(game:GetService("ReplicatedStorage"):WaitForChild("SkillTree"):WaitForChild("SkillTreeClient"))

local remotes = {
  unlockRequest = game:GetService("ReplicatedStorage"):WaitForChild("SkillTreeUnlockRequest"),
  upgradeRequest = game:GetService("ReplicatedStorage"):WaitForChild("SkillTreeUpgradeRequest"),
  stateUpdated = game:GetService("ReplicatedStorage"):WaitForChild("SkillTreeStateUpdated"),
}

local client = SkillTreeClient.new(remotes)

-- Listen for state updates
client.StateUpdated:connect(function(state)
  print("Unlocked nodes:", state.unlockedNodes)
  print("Currencies:", state.currencies)
end)

-- Request unlock
client:requestUnlock("node_id")
```

## Testing

Tests use TestEZ. Each test file exports a function that defines test suites:

- **Validator.test.luau** — 10 tests covering prerequisite evaluation
- **Tree.test.luau** — 8 tests covering unlock flow and respec
- **Store.test.luau** — 4 tests covering serialization
- **Currency.test.luau** — 5 tests covering multi-currency logic

To run tests in Studio:
1. Load a test script that requires the test files
2. Call `TestEZ.TestBootstrap:run({testModules})`

## Moonwave Documentation

Generate HTML docs from Moonwave comments:

```bash
# Install moonwave (if not done)
luarocks install moonwave

# Build docs (HTML in ./site/)
moonwave build --out-dir site

# Markdown guides for the site live in ./docs/; landing page in ./pages/
```

Every public function, type, class, and property has Moonwave comments:
- `--- @class ClassName` — Class definition
- `--- @interface TypeName` — Interface definition
- `--- @prop name Type` — Property documentation
- `--- @param name Type -- Description` — Parameter documentation
- `--- @return Type -- Description` — Return value documentation
- `--- @within Class` — Links symbol to its parent

## Wally Publishing

To publish this package to Wally manually:

```bash
# Update version in wally.toml, then:
wally login   # once per machine, or CI uses WALLY_AUTH_TOKEN
wally publish
```

The package will be available as `metricrb/skilltree@<version>`.

### GitHub Actions

- **`.github/workflows/ci.yml`** — on every push/PR to `main`/`master`: **`wally install`**, **`wally package --list`**, **`rojo build`** (installs tools via **Aftman** + `aftman.toml`).
- **`.github/workflows/publish-wally.yml`** — publishes when you run **Actions → Publish (Wally) → Run workflow**, or when you **publish a GitHub Release** whose tag is **`vVERSION`** matching **`version`** in `wally.toml`. Add a repository secret **`WALLY_AUTH_TOKEN`** (same token you get from `wally login`; can be read from `~/.wally/auth.toml` locally).

## Customization

### Add a New Node Type

Extend the `type` union in `Types.NodeConfig` and update `Validator.luau` and `SkillTree.luau` to handle it.

### Add a New Prerequisite Type

Add a new field to `Prerequisites` type and extend `Validator.canUnlock()`.

### Add a New Layout Topology

Define the layout in config and handle rendering in your UI layer (not constrained by the core library).

### Custom UI

The example UI uses Fusion 0.3. You can substitute your own UI system; the SkillTree library is UI-agnostic.

## Performance Notes

- **State Size**: Player state is a plain Luau table (no metatables) — serializes efficiently
- **Validator**: O(1) per prerequisite type; validates at unlock time only
- **Store**: ProfileStore handles session locking and saves; SkillTree treats store as authoritative per-player session (`EndSession` on unload).
- **Network**: Batched state updates; client caches locally
- **Effect Handlers**: Run async (task.spawn) to avoid blocking unlock logic

## Security

- **Server-Authoritative**: All unlock logic runs server-side; client is untrusted
- **Prerequisites**: Validated on server with player state snapshot
- **Currency**: Server is source of truth; cannot be spoofed by client
- **RemoteEvents**: Standard Roblox security (call validation, exploitability depends on game)
